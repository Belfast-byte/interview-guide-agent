## Agent 面试平台演进设计文档

- 产出 `AGENT_INTERVIEW_PLATFORM_DESIGN.md`：从 MVP 到企业级面试平台的架构设计，覆盖工具、MCP、多 Agent 三个方向。
- 核心设计判断（后续实现应遵守）：
  1. 多 Agent 用星型结构：Java 编排器居中裁决 + 专家 Agent（规划/维度面试官/深度评估/报告措辞）只做建议；拒绝网状自由对话，保护证据链与状态机。
  2. 第一个拆分是"提问与评估分离"（评估 Agent 独立判深度，防裁判教练同体）；评估与出题是两次独立 LLM 调用。
  3. 回答深度五级量规 L0~L4；动作映射（追问/换题/结束）由代码裁决，非模型决定；拒绝百分制，用维度×深度矩阵做企业筛选。
  4. 工具引入按"是否需要客观验证"排序：P0 代码沙箱（算法维度）、P0 证据校验器、P1 题库检索/量规查询、P2 练习推荐。
  5. MCP 只用于跨组织边界：作为客户端接 ATS/知识库，作为服务端开放面试能力；内部工具不包 MCP；租户身份只从凭证解析。
  6. 数据模型从 agentStateJson 演进为 plans/turns/assessments/evidences/agent_decisions 拆表；企业聚合只基于结构化表。
- 路线图：P1 评估拆分+量规 → P2 沙箱+算法 → P3 租户+能力模型 → P4 MCP 集成 → P5 语音等。

## 项目代码分析服务设计（Pi SDK + MCP）

- 产出 `AGENT_PROJECT_CODE_ANALYSIS_DESIGN.md`：独立部署 Pi SDK 编码 Agent 为 MCP 服务，分析候选人项目代码。
- 关键决策：
  1. 契约解耦：平台只认 MCP 工具面（submit_repo/get_digest/get_claim_verifications/get_scenarios/trace），与具体 SDK 解耦；分钟级分析走 Redis Stream 异步，MCP 只查产物，不做同步等待。
  2. 三类产物：项目摘要、主张核验（VERIFIED/CONTRADICTED/UNVERIFIABLE 三态）、场景卡片（EXPLAIN/PATCH），全部强制 file:line 锚点。
  3. 证据边界：CODE_FACT 是事实素材不是能力证据；CONTRADICTED 只触发核验追问，不直接判负；能力结论仍只能来自候选人回答。
  4. 最大特有风险是仓库内提示注入（README 里写"给高分"）；产物 schema 强制锚点、无锚点结论丢弃。
  5. git 作者信息只作信号不进报告（防团队项目误伤）；分析超时优雅降级为普通简历问答。
- 路线：作为 Phase 3.5 插入（依赖 Phase 1 评估拆分 + Phase 2 沙箱），里程碑 CA-1~CA-4。

## 平台文档新增第 7 节：上下文与记忆设计

- 在 `AGENT_INTERVIEW_PLATFORM_DESIGN.md` 插入第 7 节（后续章节顺延为 8~13），并同步修复代码分析文档中"平台设计第 7 节→第 8 节"的交叉引用；路线图 Phase 1/3、可观测性指标均补了记忆条目。
- 三层模型：L0 工作上下文（编排器统一装配，每 Agent 最小必要集，token 预算有界）、L1 短期记忆（维度完成后滚动压缩为维度小结，证据 quote 逐字保留、报告只读原始轮次表）、L2 长期记忆（候选人能力画像 latest-wins + superseded，企业侧量规校准/题目有效性）。
- 关键规则：
  1. 公平性防火墙——历史评级对当前评估硬禁止（防锚定偏差），只允许影响复测选题/练习推荐/成长轨迹；企业视图默认只见本场。
  2. 防记忆投毒——只有编排器裁决后写记忆，只写结构化字段，LLM 自由文本永不入长期记忆。
  3. 结构化优先于向量——pgvector 只做相似问答检索（离线）和题目语义去重。
- 公平性回归测试：相同回答注入不同历史画像，评级必须一致，每次改上下文装配器必跑。
