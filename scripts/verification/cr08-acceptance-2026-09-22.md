## 真实质量问题与本次修改

1. **题目条件仍有缺口。** 生成题要求处理扣减后插入记录失败，但未公开两个调用的事务参与条件。私有参考还要求重复请求返回既有结果，却没有提供读取既有结果的接口。
2. **参考混入假设中的修复错误。** 原代码没有调用数据库扣减，参考 C6 却把“扣减成功后插入失败未回滚”列为原代码缺陷。这是可能由修复引入的问题，不能当成原题已存在的缺陷。
3. **代码关联文字评估存在知识误判。** 报告要求候选人说明 `ConcurrentHashMap.compute` 在并发冲突下重试回调的机制。Java 21 的具体方法契约规定一次 compute 调用只调用一次回调，不能混淆其他 Map 实现。已按 [Java 21 官方 API](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/util/concurrent/ConcurrentHashMap.html#compute(K,java.util.function.BiFunction)) 核对；原正式报告作为失败证据保留，没有改写历史评估。
4. **练习创建结构失败。** 连续真实请求出现 MismatchedInputException。一次临时诊断仅记录字段路径，定位到 `initialQuestion.targetOrder` 缺失；诊断已移除。随后明确首题对象完整结构和必须显式填写 0，给既有字段补充 schema 描述，并增加缺失/null 仍被拒绝的回归。复验越过解析阶段后触发重复主题拒绝，不能据此宣称创建全部通过。

Planner 与 Interviewer 的出题提示已补充参数/存在性、事务参与和准确业务后果要求，要求私有验收项与初始代码及公开契约对应。练习 Planner 同时明确单主题只生成一个维度、历史其他主题不扩大用户范围。这些是既有边界的明确表达，没有增加代码题数量限制、自动重试、静默补值或沙箱执行。

上述修改不能消除所有模型语义错误。CR-08 仍需按后续真实练习复验及质量校准结果判定，不以测试或 schema 通过替代质量通过。
