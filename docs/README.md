# 文档中心

项目文档按“设计意图—技术规格—历史记录”分层，避免把 Agent 生成的实现细节变成用户的设计维护负担。

| 目录 | 维护主体 | 回答的问题 | 内容 |
|---|---|---|---|
| [`design/`](./design/README.md) | 用户主导 | what / why | 自然语言描述的目标、范围、非目标、业务约束、关键裁决与框架性设计 |
| [`design_spec/`](./design_spec/README.md) | Agent 主导 | how | 代码现状、模块/API/数据契约、时序、迁移、测试、验收、执行计划与 tickets |
| [`archive/`](./archive/) | 仅归档 | 历史上如何设计 | 已被取代的基线与早期探索 |

## 权威关系

1. 产品与架构意图以 `design/` 为准。
2. `design_spec/` 从相关设计派生，不得静默增补或改写用户决策；发现冲突时必须显式暴露。
3. 代码与测试是当前运行事实。实现变化后由 Agent 更新技术规格，不要把同步负担转给 `design/`。

阅读时先看相关自然语言设计，再按任务进入对应技术规格。
