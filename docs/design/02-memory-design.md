# 三层记忆设计

> 状态：当前架构裁决。本文只描述职责和边界，具体模型、存储与实现由 Agent 在 `design_spec` 中维护。

记忆分为三层，分别回答三个问题：

- **Working Memory**：本场现在怎么做。
- **Episodic Memory**：过去具体发生了什么。
- **Semantic Memory**：长期表现说明了什么。

## 1. Working Memory：本场运行状态

Working Memory 是单次面试或练习中持续变化、可恢复的运行状态。它保存当前能力目标、活动证据、未闭环问题、注意力焦点、剩余预算和下一动作意图。

正式评估只根据当前 JD、最新简历、岗位能力模型和候选人级别初始化；练习模式还可以根据长期能力与历史薄弱点初始化。

评估结果、工具结果和动作执行结果都通过结构化 Patch 更新状态。Agent 负责提出 Patch，确定性代码负责校验和应用。调用工具等外部动作前，必须先保存动作意图，以便故障后恢复且不重复执行。

下一动作策略读取完整状态，决定继续追问、调用工具、切换目标或结束。Interviewer、Assessor 和 Tool Router 只看到各自需要的裁剪视图。

## 2. Episodic Memory：可审计的具体经历

Episodic Memory 按轮记录真实发生的事情，包括问题、回答、评级、证据、工具结果、问题如何产生，以及某个 gap 是解决、未解决还是被放弃。正式评估和练习都会产生 Episode。

事实记录不可覆盖；候选人后来纠正错误，应形成新的 Episode，并回连之前的经历。事实骨架随本轮结果可靠落库，摘要、标签和相似场景索引可以异步生成。

同一份 Episode 按使用场景提供不同视图：

- **正式评估**只读取题目、场景和相似度等中性信息。Interviewer 先出题，再召回历史 Episode；如果题目考过，就保持知识点、难度和证据要求不变，换成新的业务场景。当前模块恰好覆盖历史未闭环问题时，也可以生成中性的重新验证题，但不能把历史答案和评级交给 Interviewer 或 Assessor。
- **练习模式**可以读取完整经历，包括历史回答、评级、证据、gap、提示和工具使用情况，用来进行针对性追问、反例训练、工具演示和无提示复测。

题目去重不等于知识点去重。相同知识点可以重新验证，但不能只换措辞；应改变场景、约束或验证方式，同时保持原计划的难度边界。

## 3. Semantic Memory：可修订的长期认识

Semantic Memory 从多次 Episode 中归纳稳定能力、反复出现的错误模式和回答习惯，并保留支持与反驳它的经历来源。它不是当前面试的事实，只是可被新证据修订的长期认识。

正式评估能力与练习掌握度必须分开：

- **评估能力**只由正式评估经历更新，表示候选人在独立条件下展示出的能力。
- **练习掌握度**只由练习经历更新，并区分独立完成、追问后完成、提示后完成和工具辅助完成。

两种模式都生产 Semantic Memory，但只有练习 Planner、成长报告和推荐系统消费它。正式评估的 Planner、Interviewer 和 Assessor 都不读取长期能力画像。练习中掌握了某个知识点，也不能覆盖正式评估结论；只有后续独立评估才能确认学习成果已经迁移。

## 4. 两种模式的数据流

```text
正式评估：
JD / 简历 / 岗位要求
  → Working Memory
  → 出题后召回 Episode 做去重或中性重验证
  → 仅按本场证据评估
  → 写入 Episode
  → 更新评估能力，供练习使用

练习模式：
Semantic Memory + 完整 Episode
  → Working Memory
  → 针对薄弱点追问、提示、工具演示和复测
  → 写入 Episode
  → 更新练习掌握度
```

## 5. 关键边界

1. 当前会话证据始终高于历史记忆。
2. Agent 只提出状态变更，确定性代码维护状态和动作。
3. Episode 是不可变经历，Semantic 是可修订归纳，两者不能混为一份画像。
4. 历史表现不能改变正式评估的模块分布、轮次预算和深度上限。
5. 正式评估可以利用 Episode 避免重复题目，但不能读取历史能力结论。
6. 历史评级可以决定练习什么，不能决定本次回答的评级。
7. 工具结果可以证明客观事实，不能单独证明候选人的能力。

最终边界是：**正式评估生产记忆但对长期能力保持盲视；练习模式同时生产和消费记忆，以形成持续学习闭环。**
