## 1. 问题与范围

使用原失败会话 `d7eb33bb-039a-4954-95ab-ccbfd24c48b4` 的第 5 轮答案和原模型配置重放：Assessor 输入估算 10,976 token，真实模型调用成功；Interview Agent 输入估算 21,043 token，超过当前 20,000 上限，在首次出题调用前被本地拦截。

出题输入主要包括固定 Skill 参考 8,756 token、全场历史 5,593 token、系统提示与 Schema 4,008 token、计划与覆盖情况 2,172 token。当时工具结果为空，5 轮均为文字题，没有源码或采用量规正文累积。

本次只做：

- 将出题默认加载的专业参考替换为精简岗位出题说明。
- 将专业参考接入现有向量基础设施，由模型通过 RAG 工具按需获取。
- 限制新工具结果的上下文占用，补充 token 分项观测并重放验收。
- 验证 Assessor 输入及正式量规采用语义保持原样。

Planner 不改，也不新增人格加载。历史窗口与历史去重留作后续治理；本次不承诺解决所有长会话超限。

## 2. 精简出题 Skill

每个预设 Skill 增加 `decision.md`，人工维护岗位特有的提问重点和追问策略，不由模型每场总结生成。现有 `SKILL.md` 和参考资源保留原用途。

`ContextAssembler` 对本场 Plan 涉及的不同 Skill 加载 `decision.md`，替换当前 `buildEvaluationReferenceSection()`。同步调整内部上下文及 `DecisionContextProjection` 的字段命名，明确内容是出题说明，不再是评估参考。

公共规则继续放在出题系统提示中，包括单题输出、数据边界、不给答案、工具协议及代码题约束，避免在每个 Skill 重复。保留全部计划 Skill 的简短说明，让模型自主选择目标，不由 Java 预选下一题。

不改公开 API、Plan 存储或历史记录；旧会话根据既有 `suggestedSkill` 使用新说明。缺失的预设 `decision.md` 在资源校验中暴露，不静默退回全量参考。

## 3. 参考检索复用现有 RAG

复用现有 Embedding、pgvector、`VectorStore`、`ReadOnlyAgentTool`、`ToolGateway` 和 Agent Loop，不另建向量服务、工具执行框架或目录分页系统。

### 数据接入

- 按 `skill.meta.yml` 的实际映射读取专业参考，按章节和 token 长度分块。
- 同一资源被多个分类引用时去重，保留对应 Skill / focus 关联。
- 使用独立 `document_type=skill_reference`，记录资源标识、片段标识和范围元数据，与 rubric、题库及用户知识库区分。
- classpath 资源是这类内置资料的内容依据；向量是可重建索引。检索结果须核对当前资源及映射，不能把已删除、失效的索引内容当成有效资料。
- 为资源新增、修改、删除提供明确的索引同步入口。首版不复制 rubric 生成审核流程，也不新增任务队列、租约或恢复状态机；首次导入和更新后以完成检索验证作为发布验收项。

### 模型工具

新增薄工具 `reference_search`，参数为：

```json
{
  "targetId": "本场实际目标ID",
  "query": "希望查找的专业问题或机制"
}
```

后端从本场 Plan 的目标解析 `skillId + focusId`，据此限定可检索参考；严格校验参数，不接受模型传入路径、owner、sessionId 或任意知识库 ID。命中返回标题、相关片段和来源标识。

模型自行判断是否检索，信息足够即可出题；不增加每轮必调的参考步骤。无命中返回 `TOOL_EMPTY`，检索或索引不可用返回 `TOOL_ERROR`，不以全量参考注入作为降级。

### 与 rubric 的边界

`rubric_search` 继续检索 ACTIVE 题库量规，并沿用版本校验、采用来源和发布时冻结快照的流程。专业参考只是出题背景，不写入 `scoring_rubric`，不伪装成 `rubric:` 来源。

`reference_search` 首版返回空的 `adoptableSources`，不新增持久化来源类型，不将参考正文写入 WorkingMemory 或评分事实。两个工具共享检索基础设施，各自保持明确的返回语义；不为相似的几行调用代码新增通用检索抽象。

## 4. 输入预算与观测

新工具同时限制返回条数和总 token，占用须结合当前 Loop 已有上下文计算，并为下一次决策预留空间。按完整片段去重、选取，不把半段正文冒充完整资料。空间不足时返回明确的预算提示；最终模型调用仍经过 token 检查。

首版片段大小、召回数和总预算以原会话测试确定，不能只设 `topK`，也不能依赖当前没有消费者的 `maxResultChars`。重复检索时避免在模型输入中累积同一来源片段；必要的工具执行与校验信息仍留在请求内。

记录角色、轮次、Loop 步骤、输入上限，以及系统提示、Skill、历史、覆盖情况、工具结果的估算 token，不记录答案或参考正文。当前应用 20,000 上限不作为本次调大项。

## 5. 实施与验收

按出题上下文调整、参考 RAG 接入、观测与回归分批实施；如实现需要数据库迁移，单独提交，不改已执行迁移。

1. 默认出题输入只有精简 Skill，不含专业参考全文，Planner 输入保持原样。
2. RAG 能在本场目标范围内返回相关资料；覆盖非法参数、越界目标、无命中、索引不可用、资源更新删除和重复片段。
3. 新工具结果遵守预算，读取参考后不会因无界回传再次超限。
4. 重放原第 5 轮，记录首次及工具调用后的出题输入，验证正常生成下一动作；补充后续轮次验证，不以单轮成功证明所有长会话安全。
5. Assessor 的相关参考、原文证据、量规快照和正式评分流程保持原样。重放不提交新评分或下一题，保留原失败现场。
